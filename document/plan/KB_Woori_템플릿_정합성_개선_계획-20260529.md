## Implemented Contract

- Template chart profile
  - KB는 template image에 chart가 없으므로 `fallbackChartType=bar`를 사용한다.
  - Woori는 template image 분석 결과 chart가 있으므로 `detectedChartType=bar`를 우선한다.
  - Stage 4 chart type은 Stage 2 `chartSpec.type`이 아니라 template `chartProfile` 기준으로 결정한다.

- Stage 3 validation and repair
  - Stage 3는 initial HTML 생성 후 local validator를 통과해야 한다.
  - 실패 시 correction prompt를 최대 3회 호출한다.
  - correction 3회 후에도 source fragment 누락/변형이 남으면 local repair가 해당 non-chart component의 내부 HTML을 Stage 2 원문으로 복원하고 다시 validator를 실행한다.
  - local repair는 chart placeholder, component id, document-local CSS, footer flow, chart rendering 금지 등 기존 validator 계약을 우회하지 않는다.
  - `03_layout/layout_validation_loop.json`과 `03_layout/attempts/attempt_*_report_draft.html`로 attempt 이력을 남긴다.

- Stage 5 verification
  - 템플릿 이미지는 layout/style 기준이다. 템플릿 이미지의 샘플 텍스트, 수치, 종목명, 섹션명, 표 컬럼명은 데이터 기준이 아니다.
  - 데이터 기준은 Stage 2 component HTML과 현재 report HTML이다.
  - `missing_content`와 `data_mismatch`는 Stage 2/HTML 대비 preview 누락 또는 변경에만 사용한다.
  - `template_mismatch`는 템플릿 대비 visual structure/style 차이에만 사용한다.
  - `componentMode=novita`에서는 `verificationMode=manual-pass`를 허용하지 않는다.

- Max iteration and finalization
  - `--max-iterations`는 사용자가 지정 가능하며 CLI 기본값은 3이다.
  - 모든 attempt가 fail이고 마지막 결과도 revision을 요청했으면 loop result에 `maxIterationsExceeded=true`를 기록한다.
  - 이 경우 job을 실패시키지 않고 `bestFailedVersion`을 `final/`로 복사한다.
  - best failed fallback final은 검수 통과물이 아니므로 `verificationPassed=false`, `finalizationReason=best_failed_after_max_iterations`를 기록한다.
  - `verificationScore`는 penalty 점수이며 낮을수록 좋은 후보로 해석한다.

## Remaining Improvements

- Woori template mismatch 해소
  - 현재 Stage 5가 반복해서 지적하는 항목은 header/footer logo, section marker, performance summary/table style, chart legend 위치다.
  - LLM revision만으로 수렴하지 않으므로 Woori용 deterministic layout skeleton 또는 이미지 기반 strict visual comparator가 필요하다.

- KB/Woori deterministic layout profile renderer
  - `report_templates.json`에 `layoutProfile`을 추가하는 후속안을 유지한다.
  - KB 후보: `strategy=kb_dense_fact_sheet`, template size `1190x1600`, dense table-first layout, compact bar chart region, 2-column holdings, compact review/outlook, KB header/tagline/footer style.
  - Woori 후보: `strategy=woori_monthly_report`, template size `1240x1754`, Woori header/footer/section marker/chart/table region skeleton.
  - profile renderer 사용 시에도 Stage 3 validator와 Stage 4 chart injection을 그대로 통과해야 한다.

- Stage 5 strictness
  - Stage 5 prompt에는 chart source precedence를 계속 명시한다.
  - `templateImageHasChart=false`인 템플릿에서는 template image에서 chart type을 추론하지 않고 `fallbackChartType`만 기준으로 검수한다.
  - chart type 변경 지시가 template chart profile과 충돌하면 chart type 변경이 아니라 chart style mismatch로 정규화한다.
