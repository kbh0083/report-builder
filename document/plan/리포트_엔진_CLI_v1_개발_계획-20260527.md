## 1. 개발 목표

CLI v1의 목표는 HTTP API, SSE, frontend 없이 backend 엔진 코어를 먼저 구현해 터미널 명령 한 번으로 최종 HTML 리포트와 preview image를 생성하는 것이다.

구현 완료 후 사용자는 아래 형태의 명령으로 리포트 생성을 실행할 수 있어야 한다.

```bash
python -m report_engine run \
  --dataset-id data_kodex_us_sp500 \
  --template-id tpl_kb_monthly_guidebook \
  --month-id 2026-03 \
  --component-mode sample \
  --layout-mode novita \
  --verification-mode manual-pass \
  --max-iterations 3 \
  --output-dir runs
```

CLI v1은 아래 산출물을 생성한다.

```text
runs/
  {jobId}/
    job.json
    events.jsonl
    v1/
      report.html
      preview.png
      verification.json
    final/
      report.html
      preview.png
```

## 2. 핵심 결정 사항

### 2.1 데이터와 템플릿 독립 선택

기존 설계 문서에는 데이터셋 내부 템플릿 메타를 기준으로 데이터셋과 템플릿이 결합된 전제가 남아 있었다. 실제 구현에서는 이 결합을 끊는다.

변경 후 요청 모델은 아래 3개 식별자를 독립 입력으로 받는다.

| 필드 | 의미 | 예시 |
|---|---|---|
| `datasetId` | 상품/월별 데이터 선택 | `data_kodex_us_sp500` |
| `templateId` | 시각 템플릿 선택 | `tpl_kb_monthly_guidebook` |
| `monthId` | 기준 월 선택 | `2026-03` |

템플릿은 데이터에 의존하지 않고, 데이터도 템플릿에 의존하지 않는다. 예를 들어 국민은행 데이터에 우리은행 템플릿을 적용하거나, 우리은행 데이터에 국민은행 템플릿을 적용하는 조합도 repository 단계에서 허용한다.

### 2.3 CLI v1 범위

CLI v1에 포함한다.

- 데이터/템플릿 카탈로그 분리
- backend Python package 골격
- repository 계층
- Stage 1 템플릿 선택/파일 검증
- Stage 2 sample adapter
- Novita LLM adapter 경계와 secret redaction
- Stage 3 layout generation 경계
- Stage 4 HTML 저장 및 preview rendering
- Stage 5 `manual-pass` 검증 모드
- Stage 6 final alias 생성
- CLI JSON lines progress 출력
- `job.json`, `events.jsonl`, version 산출물 저장
- API key 비노출 검증

CLI v1에서 제외한다.

- HTTP API
- SSE progress stream
- frontend 화면
- 사용자 인증/권한
- object storage/DB 저장
- 운영용 A4 다중 페이지 pagination
- Novita 실호출을 필수로 하는 자동 테스트

## 6. 완료 정의

CLI v1 개발은 아래 조건을 모두 만족하면 완료로 본다.

- `datasetId`, `templateId`, `monthId`를 독립 입력으로 받는다.
- template과 dataset의 판매사/출처가 달라도 실행 가능하다.
- sample component 경로로 Stage 1~6 전체 실행이 가능하다.
- final HTML과 preview PNG가 생성된다.
- job metadata와 event log가 생성된다.
- 자동 테스트는 API key 없이 통과한다.
- 실제 API key 값은 로그, 산출물, 문서에 남지 않는다.
- API/SSE/frontend는 구현하지 않는다.

## 7. 주요 리스크와 대응

| LLM이 원천 수치/문구 변경 | 보고서 신뢰성 저하 | Stage 3 출력에 component id와 원천 fragment 보존 검증 추가 |
| API key 노출 | 보안 사고 | settings/redaction과 보안 테스트를 초기 task에 포함 |
