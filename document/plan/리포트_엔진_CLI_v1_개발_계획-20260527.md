## 1. 개발 목표

CLI v1의 목표는 HTTP API, SSE, frontend 없이 backend 엔진 코어를 먼저 구현해 터미널 명령 한 번으로 최종 HTML 리포트와 preview image를 생성하는 것이다.

구현 완료 후 사용자는 아래 형태의 명령으로 리포트 생성을 실행할 수 있어야 한다.

```bash
python -m report_engine run \
  --dataset-id data_kodex_us_sp500 \
  --template-id tpl_kb_monthly_guidebook \
  --month-id 2026-03 \
  --component-mode sample \
  --layout-mode novita \
  --verification-mode novita \
  --renderer-mode playwright \
  --max-iterations 3 \
  --output-dir runs
```

CLI v1은 아래 산출물을 생성한다.

```text
runs/
  {jobId}/
    job.json
    events.jsonl
    v1/
      report.html
      preview.png
      verification.json
    final/
      report.html
      preview.png
```

## 2. 핵심 결정 사항

### 2.1 데이터와 템플릿 독립 선택

기존 설계 문서에는 데이터셋 내부 템플릿 메타를 기준으로 데이터셋과 템플릿이 결합된 전제가 남아 있었다. 실제 구현에서는 이 결합을 끊는다.

변경 후 요청 모델은 아래 3개 식별자를 독립 입력으로 받는다.

| 필드 | 의미 | 허용 값 |
|---|---|---|
| `datasetId` | 상품/월별 데이터 선택 | `data_kodex_us_sp500_h`, `data_kodex_us_sp500`, `data_kodex_us_nasdaq100`, `data_kodex_korea_dividend_growth_bond_mixed` |
| `templateId` | 시각 템플릿 선택 | `tpl_kb_monthly_guidebook`, `tpl_woori_monthly_report` |
| `monthId` | 기준 월 선택 | `2026-01`, `2026-02`, `2026-03` |

템플릿은 데이터에 의존하지 않고, 데이터도 템플릿에 의존하지 않는다. 예를 들어 국민은행 데이터에 우리은행 템플릿을 적용하거나, 우리은행 데이터에 국민은행 템플릿을 적용하는 조합도 repository 단계에서 허용한다.

   - 5개 중 하나라도 timeout, invalid JSON, style/class 규칙 위반, component id 누락이 발생하면 Stage 2 전체를 실패 처리하고 Stage 3로 partial 결과를 넘기지 않는다.

   - componentKey 순서: `performance_chart`, `performance_summary`, `top_holdings`, `review`, `outlook`

   - `performance_chart`만 `chartSpec` object 허용
   - 나머지 4개 컴포넌트의 `chartSpec`은 `null`

10. Stage 2 fragment는 무스타일 상태를 유지하고, 모든 표현 스타일은 Stage 3에서만 생성한다.
11. Novita/fake adapter 기반 Stage 3 출력은 단일 HTML 문서여야 하며, `<style>` block 또는 동등한 document-local CSS를 포함해야 한다.
12. Stage 3 CSS는 외부 CSS 파일, 외부 font, 외부 network resource, script를 사용하지 않고 HTML 내부에 포함한다.
13. Stage 3 CSS는 A4 portrait layout, header/footer/brand, section spacing, typography, table/list/article styling, bottom safe area를 담당한다.
14. 출력 HTML에 5개 component id가 모두 포함되는지 검사한다.
15. Stage 3 출력에 SVG, canvas, script, Chart.js 등 chart rendering markup이 있으면 `LAYOUT_GENERATION_INVALID`로 실패한다.
16. Stage 3는 chart를 렌더링하지 않고 `data-chart-placeholder` container의 배치와 공간만 스타일링한다.
17. Stage 3 출력에서 footer 또는 하단 고지 문구가 `position:absolute`/`position:fixed`를 사용하면 `LAYOUT_GENERATION_INVALID`로 실패한다.

19. Novita/fake adapter 기반 Stage 3 출력에 document-local CSS가 없으면 `LAYOUT_GENERATION_INVALID` 대상이다.
20. `LLM_API_KEY`는 prompt, event, exception, job metadata에 기록하지 않는다.

- LLM 기반 Stage 3 draft는 layout + CSS 포함 단일 HTML로 생성된다.
- Stage 5에서 Novita LLM이 template image, preview image, HTML을 검증하고, issue JSON 또는 통과 결과를 생성한다.
- Stage 5에서 수정 지시가 생성되면 Stage 3/4를 재실행해 새 version을 만들고 `maxIterations` 내에서 재검증한다.
- `maxIterations`는 CLI 사용자가 지정 가능하고 기본값은 3이다.
- max iteration 소진 후 passed version 부재 시 best failed version이 final로 복사되고 `verificationPassed=false`가 기록된다.
- LLM 경계 변경 후에는 실제 Novita CLI smoke 결과 또는 미수행 사유가 검증 결과에 기록된다.
- Stage 4에서 template chart profile 기준 chart type으로 `performance_chart.chartSpec` 데이터가 렌더링되고 placeholder가 교체된다.
- final HTML과 preview PNG가 생성된다.
- job metadata와 event log가 생성된다.
- job status는 `queued`, `running`, `passed`, `failed`, `cancelled` 중 하나로 기록된다.
- 자동 테스트는 API key 없이 통과한다.
- 실제 API key 값은 로그, 산출물, 문서에 남지 않는다.
- API/SSE/frontend는 구현하지 않는다.
